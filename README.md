# rehud_test_harness

Install: copy `main.lua` and `metadata.xml` over to `mods\rehud_test_harness` in the game folder and delete `disable.it` there; put `disable.it` back after each session.

On the first new run after launch, on save slot 1 (unlocked there: Cain, Eve, Samson, Lazarus, Lilith, The Forgotten, J&E, Tainted Lazarus, Tainted Forgotten), it plays the scenarios in `SCENARIOS` by itself; the user only starts the run, exits and continues when the screen says so, and exits to the menu after DONE (that flushes `log.txt`).

Each scenario is `kind = "small"` (passes on its own) or `"large"` (needs the user's exit and Continue; runs last, back to back, each asking for its own); a large one carries `new = true` until it has passed in game, then clear the flag; set it again whenever its steps or checks change.

Mode: before launch, write the plain text `regression` into `data\rehud_test_harness\save1.dat` in the game folder (vanilla `SaveData` path, `data\<metadata directory>\save<slot>.dat`) to run every scenario before a release; `only <prefix>` runs just the scenarios whose name starts with it (`only obs`: every `obs` scenario, `obsx` and `obsy` included); any other content, or no file, runs all small scenarios and only the new large ones.

`only` takes comma-separated prefixes: `only final,S3,r1,P4c` checks ReHUD 2.8's final build (the `final` scenarios plus the regression checks S3, r1, r1 mirror and P4c). `final A`-`G` are checked: each character, told apart by the harness's own `GetData` tag, needs its own row, and a stored one its items from its last live update (`ROWS` line per character per look); F and G are observations whose failures are expected data. `final I`-`N` are observation only (OBS lines every update, steps and ceilings as `obsx`); `final N` is `large` and asks for an exit and Continue. A step the harness cannot do (a pedestal walk that never touches) shows `YOU: ...` on its own screen line. `tools\report.py --timeline <test>` also prints a `final` test's timeline.

`only obsx` runs the dispute scenarios. An `obsx` step that fails, or still waits after 120 updates, logs INFO and ends its scenario (a failed `obs` step is only skipped); each `obsx` scenario stops at 445 updates, setup and settle waits included.

`only obsy a` and `only obsy b` run the `obsy` follow-ups to obsx runs 1-4, steps and ceilings as `obsx` (a Continue scenario stops at 1000 updates, 600 of them for the user's exit and Continue); worst cases 4497 and 3942 updates, both under 3 minutes of updates (mode b's wall-clock time also includes three menu-and-reload pauses for the Continues, about 160 s); `only obsy` runs both, 8382 updates (4.7 minutes) at worst. The three Continue ones (`obsy b continue ...`, `obsy b identity`) are `large`, not `new`: default mode skips them. Each `obsy` Esau Jr. press (`jr`), each `flipV` Flip and the Clicker press in `obsy a schoolbag Clicker` logs `INFO <scenario> VERDICT <press> index <i> <before> -> <after> new|returned|moved from <j>|unchanged [(t<a>-><b>)] | <lineup> -> <lineup>` (`moved from`: a character that held another index before, as a Birthright Flip swaps the twins; the type pair when the character stayed but its type changed), characters labelled A, B, C... by GetPtrHash in first-seen order, as the snapshot labels them (`index:label(t<type>)`, the seed after `=` on first sight); each Esau Jr. press logs `TIMING` lines: the pressed index's occupant once per game frame for 5 frames from its first new seed (c703 owned, slots), until a seed other than that first new one holds it. A Continue answered after its step gave up, during the next scenario only, logs `late Continue, ignored`, adds `; late Continue mid-scenario` to that scenario's `RESULT` line, and the run carries on; any later Continue is unexpected. In an `obs` scenario, a press that spends the charge but keeps the pressed index's seed and type passes when that index's entity (`GetPtrHash`) or items changed, logged as `new form, same seed <seed>, hash <a> -> <b>` or `acted in place: same seed <seed>`, with `items <before> -> <after>` (after a Continue, run 1). When the presser's seed no longer holds the item after a swap (a Birthright swap moves it to the twin), its spend is read on the pressed index. `obsy b identity` logs `IDS` per player (InitSeed, DropSeed, Index, GetPtrHash, Collectible/Card/Pill/Trinket RNG seeds, Other/MainTwin as a GetPlayer index), each read under pcall. Eden and Tainted Jacob are locked on slot 1: a restart that never gives the type ends the scenario with `obsx ceiling 120 updates: player 0 is type <n> (character locked?)` (or `no new game`).

The `HARNESS START` line logs the mode, the mod name and the raw data read; a skipped one logs `RESULT <name> SKIP`.

A wait (action, look or settle) still unfinished after 60 updates logs `PROBE STUCK` and writes `STUCK <n> <scenario> | <step>` as the second line of that mode file (only its first line sets the mode); `tools\stuck-shots.ps1` screenshots the game window for each new STUCK line, so start it before launching the game: `pwsh -File isaac-test-harness\tools\stuck-shots.ps1 -Out <folder>`.

Each action polls its postcondition and probes wait for ReHUD to settle; a swap (Flip, Esau Jr., Clicker, Soul of J&E) is a real button press through `MC_INPUT_ACTION` and passes only with a new character plus the spent charge or card; a stored presser's spend (Esau Jr., Flip without Birthright) is read on its seed before the engine stores it (`..\lua-api-notes.md`), and a swap with no such reading FAILs. `probes` re-checks engine facts the checks rely on. Probes read ReHUD state through the permanent `ReHUD.dbg` hook (tracker, config, roster).

Results: `PROBE RESULT <scenario> PASS|FAIL|INFO` in `log.txt`, with a `PROBE CHECK FAIL` line per failed check. Every settled look also checks five invariants (engine vs ReHUD counts, duplicates, phantom stored forms, `left` entries, floors not later than the current one).

After a run, copy `log.txt` and run `.venv\Scripts\python -B -I isaac-test-harness\tools\report.py "<log path>"`; it ends with `ALL PASS` or `NEEDS ANALYSIS: <reasons>`, and only the latter needs an analysis agent. It writes `report.json` and the traces of failed, new or changed tests beside the log (`--out` elsewhere), and compares and writes `specs\<spec>.snap.txt`.

The `obs` scenarios have no checks (INFO only, a step that never happens is logged and skipped): they log `PROBE OBS` lines of engine and ReHUD state on every update it changed; `tools\report.py "<log path>" --timeline <test>` prints one test's as a timeline, characters labelled A, B, C... by GetPtrHash, with a per-character summary. Add new scenarios (ReHUD or other mods) to `SCENARIOS` instead of typing console steps. Dry run: `.venv\Scripts\python -B -I isaac-test-harness\tests\test_harness.py isaac-test-harness\main.lua`.
